## 二、发现的问题归纳

1. **数字输入（digit / number）没有页面内完成操作**
   - 微信 `input` 的 `confirm-type` 仅对 `type="text"` 生效，digit/number 不能依赖系统完成键。
   - 受影响：账单金额、日价金额、周期金额、周期间隔、每日预算。
   - 风险：iPhone 数字键盘无「完成」，用户只能点空白处或切换控件；金额输入后无法自然继续选择分类/填写商户。

2. **恒 false 的 `focus` 属性**
   - bill-form / daily-value-form 的 `focus="{{autoFocus}}"` 中 `autoFocus` 始终为 false，属无效接线。
   - 计划替换为真正的独立焦点键（默认 false，聚焦/失焦时切换）。

3. **失焦未显式同步最终值**
   - digit/number 仅依赖 `bindinput`；未绑定 `bindblur`。
   - 计划：blur 复用同一套规范化/夹取逻辑同步值，但**不在 blur 中收键盘**，避免用户从金额切到商户时键盘被强制关闭再弹起。

4. **文本输入系统完成键未接线**
   - 商户、备注、日价名称/备注、周期备注、分类名称、Emoji 均无 `bindconfirm`。
   - 计划统一 `confirm-type="done"` + `bindconfirm`：同步最新值 + 收键盘；不提交表单、不关闭 Sheet。

5. **搜索确认缺失**
   - `pages/search/search.wxml` 已有 `confirm-type="search"`，但无 `bindconfirm`，系统搜索键无响应。
   - 计划补充确认事件：清除未执行的 debounce、同步关键词、立即执行现有筛选、收键盘；保留结果与清空按钮。

6. **弹窗/返回与键盘的生命周期**
   - 删除账单、删除周期规则、周期补记确认、预算保存均可能发生在键盘打开状态。
   - `components/bottom-sheet` 已实现「先收键盘再播放关闭动画」，无需重写；`components/page-header` 已实现「收键盘后返回」，但任务要求键盘打开时首次返回只收键盘，需在既有逻辑上加一层只读判断。
   - `utils/viewport` 已监听键盘高度与窗口恢复，**不新增第二套监听**。

7. **无 `<textarea>`**
   - 全项目未使用 textarea，无多行输入场景。
