## 3. 性能基线（改动前）

### 3.1 环境

| 项 | 值 |
| --- | --- |
| 机型 | AMD Ryzen 7 5800H（笔记本，未锁频） |
| OS | win32 10.0.26200 |
| Node | v24.22.1 |
| 文件系统 | 内存 FS（`Map`），不触碰真实账本 |
| 造数 | `scripts/generate-realistic-ledger.js`，seed=20261029、anchor=2026-10-29 |
| 导入文件 | 3,000 行支付宝 CSV（`buildAlipayCsv`，固定生成规则） |
| 取样 | 每档 5 轮取中位 |

> 口径：Node + 内存 FS，不含真机文件 I/O、`setData`、WXML 渲染；数字只用于同环境纵向对照。

### 3.2 关键路径（`tests/perf/v1.4.0-keypath.perf.js`）

| 账本规模 | 月份分片 | 导入预览（3k 行） |
| --- | --- | --- |
| 5,000 | 37 | **225.4 ms** |
| 15,000 | 61 | **636.2 ms** |
| 30,000 | 85 | **1,550.4 ms** |

### 3.3 分阶段基线（`tests/perf/dedupe.perf.js`，5 轮中位）

| 账本规模 | parse | adapt | validate | dedupe | 合计 |
| --- | --- | --- | --- | --- | --- |
| 5,000 | 5.4 ms | 9.3 ms | 0.4 ms | **206.9 ms** | 221.9 ms |
| 15,000 | 1.9 ms | 7.8 ms | 0.4 ms | **343.4 ms** | 353.5 ms |
| 30,000 | 1.9 ms | 7.6 ms | 0.5 ms | **1,608.2 ms** | 1,618.2 ms |

结论：耗时几乎全部集中在 `dedupe`（`store.rangeBills()` 全量读分片 + `findSuspect()` 逐条线性扫描），与 v1.4.0 性能报告「§九③ P2」的判断一致。

> 与任务书引用的 3,039 ms 差异：本机 Node v24 + 内存 FS 重新测得 1,550 ms，按任务书要求**以本次实测为正式基线**，旧数字仅作历史参考。

## 4. 本轮待处理问题清单（Gate 1–4 输入）

| # | 问题 | 位置 | 现状证据 |
| --- | --- | --- | --- |
| 1 | 隔离失败后仍继续删除原始分片 | `data/quarantine.js` + `data/backup.js` | `quarantineUnreadableMonths()` 内部吞掉所有失败并返回；`restoreBackup()` / `rollback()` 无条件继续 `fs.remove()` |
| 2 | 恢复失败时无 mutation 状态区分 | `data/backup.js` | `catch` 无条件 `rollback()`；隔离阶段失败也会进入删除型回滚 |
| 3 | 导入去重 O(N×M) | `packages/importer/core/dedupe.js` | `findSuspect()` / `conservativeCsvMatch()` 对每条新账单全量扫描 `existing` |
| 4 | 导入 UI 全流程缺 E2E | `packages/importer/pages/**`、`tests/e2e/**` | 现有 E2E 未覆盖选择文件 → 预览 → 确认 → 结果 |
| 5 | E2E 截图发布销毁历史 | `tests/e2e/run.js:publishShots` | 发布前 `rmSync` 清空 `docs/screenshots/e2e/*.png` |
| 6 | 320px 统计 Hero 第三列可能折行 | `components/statistics-panel/statistics-panel.wxss` | `.hero__third .hero__sub` 26rpx，长金额 + 日期无单行/弹性兜底 |
| 7 | 其他 SVG 组件 rgba 兼容待审计 | `category-icon` / `cumulative-trend` / `icon` / `category-donut` | v1.4.0 已修圆环 HSL，其余仅 WARN，未逐项验证 |
