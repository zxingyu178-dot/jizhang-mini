### UI-01（P1）弹层不可滚 —— 为什么没直接改

- **平台依据**：Skyline WXSS 官方差异 —— 不支持 `overflow: scroll`，纵向滚动必须用 `scroll-view`。
- **实测几何（390×844）**：面板上限 `88% = 743px`；记账表单内容 598.4px、周期编辑器 597.6px、分类编辑器 469.9px —— **本机型不触发**。触发条件是屏幕更矮或键盘弹起（viewport 变小）后内容超高。
- **两次改造实测**（均已回滚，代码回到基线）：
  1. 内容区换成 `scroll-view scroll-y` + `flex: 0 1 auto` → **面板塌成 86.7px**（只剩拖拽条+标题），内容整块溢出屏外（`.re-save` 顶到 y=1339）；
  2. 追加 JS 计算 `max-height: 661px` → **仍然塌成 86.7px**。
  结论：Skyline 的 `scroll-view` 需要**确定高度**，而弹层高度是内容驱动的自适应高度。修复需要「JS 量内容高 → 给 scroll-view 定高」或「面板高度分段」，属组件改造，**超出本次"最小必要修复"边界**，且与 Gate 3 的键盘/viewport 域相邻。
- **建议**：单独立项（见 §7），本轮不动，避免把最高频的「记一笔」弹层改坏。

### UI-02（P2）统计金额列写死宽度（已修）

`components/statistics-panel/statistics-panel.wxss`：`.cmp-val` 由 `width:140rpx` 改为
`min-width:140rpx + flex-shrink:0 + white-space:nowrap`，金额变长时由中间进度条让位，数字不再折行/被挤。

### UI-03 / 04 / 05（P2）底部安全区（已修）

**关键实测结论**：`scroll-view` 上的 `padding-bottom: env(...)` 在 Skyline 下**不生效**。
先按「给滚动区补 padding」改，复测「添加分类」底边距仍是 **6.9px 不变**；改为**压到最后一个元素自身**才有效：

- `pages/category-manage/*`：`.cm-add` 下边距 → `calc(env(safe-area-inset-bottom) + 8rpx)`（滚到底留白 4.2 → 38.2px）
- `pages/recurring/*`：新增 `.rc-foot` 替代写死的 `height:60rpx`，实测高度 **65.2px = 34 + 31.2** ✔
- `pages/search/*`：`.day-card:last-child` 下边距 → `calc(env(safe-area-inset-bottom) + 20rpx)`

> 说明：首屏静止位置不变（内容本身接近满屏时最后一个元素仍贴底，这是长列表固有行为）；
> 修的是**滚到底**时的留白，避免被 Home 指示条压住。
