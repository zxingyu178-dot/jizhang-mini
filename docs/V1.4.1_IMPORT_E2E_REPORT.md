## 1. 文件选择自动化的边界

`wx.chooseMessageFile` 是原生文件选择器，automator 无法稳定控制。因此新增**仅 develop 可用**的注入入口：

```js
__e2eImportText(payload) {
  if (!env.isDevEnv()) throw new Error('__e2eImportText 仅开发环境可用');
  // 写 USER_DATA_PATH/__e2e_import__/<name> → detector.parseFile → 结果写 data.__e2eLast
  // 解析完成立即删除临时文件
}
```

| 约束 | 落实 |
| --- | --- |
| 仅 develop | `env.isDevEnv()` 同步前置守卫；trial / release / 未知一律抛错 |
| 不暴露 UI | `import.wxml` 无该方法引用，未注册到 `app.json` |
| 不影响真实选择 | `onChooseFile` 与 `wx.chooseMessageFile` 路径完全保留 |
| 不写正式账本 | 只解析并写 `globalData.__importSession`，确认动作仍走预览页 |
| 清理临时文件 | `.then` / `.catch` 均删除 `__e2e_import__/<name>` |

静态 / 行为测试（`tests/import-e2e-safety.test.js`，34 项）：

- 守卫位置在 `fs.writeText` / `detector.parseFile` 之前；
- 非开发环境抛错且**不写任何临时文件**；
- WXML / `app.json` 无注入入口；
- 文件选择取消不跳转、不 loading、不写会话；
- 解析失败明确弹「无法解析」、不跳转。

## 3. E2E 截图管理（非破坏性）

修复前：`tests/e2e/run.js` 的 `publishShots()` 在写图前 `rmSync` 清空 `docs/screenshots/e2e/*.png`，会删除 Git 中的历史基线。

修复后：

| 要求 | 落实 |
| --- | --- |
| 每轮独立目录 | `artifacts/e2e/<ISO 时间戳>/`，`RUN_ID` 在 config 生成 |
| 只写本轮目录 | `SHOT_DIR = ARTIFACTS_ROOT/RUN_ID`，`publishShots` 只 `mkdir + writeFile` |
| 不清空历史 | 删除 `rmSync` / `unlink`，不再遍历删除 |
| 失败保留本轮截图 | `publishShots` 在成功/失败后都执行（run.js 原有结构不变） |
| 只清理自己的临时文件 | 不再有全局清理逻辑 |
| 基线截图不被覆盖 | `docs/screenshots/e2e/` 零写入（`git diff -- docs/screenshots` 为空） |
| 产物不入库 | `.gitignore` 新增 `artifacts/` |

实测本轮产物：`artifacts/e2e/2026-11-09T02-38-41-355Z/`（18 张，全部带 `_simulator`）。
