## 1. 组合键碰撞

原实现：

```js
[
  b.type,
  b.amountCents,
  b.categoryId,
  b.note || '',
  minute
].join('|')
```

碰撞示例：

| 账单 | categoryId | note | 旧键 |
| --- | --- | --- | --- |
| A | `cat|x` | `memo` | `expense|1000|cat|x|memo|<minute>` |
| B | `cat` | `x|memo` | `expense|1000|cat|x|memo|<minute>` |

两笔分类 / 备注实际不同，旧键完全相同，可能把 `zero` 误判为 `one`，把日价补到错误账单或错误跳过。

修复：

```js
return JSON.stringify([b.type, b.amountCents, b.categoryId, b.note || '', minute]);
```

JSON 数组编码对分隔符、引号、反斜杠、空字符串都无歧义。无效时间戳仍返回 `null`（永不匹配），与原 `sameMinute(NaN, NaN) === false` 一致。

## 3. 性能（最终口径）

此前 v1.4.1 报告中出现 96.7 ms 与交付日志 118.4 ms 不一致，原因是不同轮次的机器抖动。本次在 Gate 4 重新执行 **3 轮 × 每轮 5 次中位**，原始 JSON / 日志保存于 `logs/v1.4.2/perf-run{1,2,3}.json|log`。

| 账本 | dedupe | 合计（parse+adapt+validate+dedupe） | 三轮合计范围 |
| --- | --- | --- | --- |
| 5,000 | 17.5 ms | **31.8 ms** | 29.4–39.3 ms |
| 15,000 | 54.9 ms | **70.4 ms** | 59.5–76.7 ms |
| 30,000 | 101.1 ms | **111.6 ms** | 108.9–115.1 ms |

- 5k / 15k / 30k 均无退化。
- 本报告数字与 `logs/v1.4.2/perf-run*.json` 一致，后续以这组为准；v1.4.1 的 96.7 ms 不再作为 v1.4.2 结论。
