# 真机 Scale Gate — 随时随地大小记 v1.3.0

> 用途：v1.3.0 统计大版本的**真实风格大账本真机验收门**。用 5k / 15k / 30k 三档「模拟长期使用」账本，
> 通过**正常备份与恢复**注入真机，验证统计页、分类占比、模块开关、预算、搜索、切月年度、导出在真实微信 Android 上的
> 实际等待时间、流畅度与数据正确性。Node 端耗时不能替代真机，本 Gate 由用户本人执行，助手不代签。
>
> 状态记录约定：`Agent simulator: PASS`（已跑）；`User physical device: PASS | FAIL | NOT TESTED`（待用户回填）。

## 2. 注入步骤（走正常恢复，不走开发后门）

1. 把对应 `.dvmini.json` 发送 / 保存到真机微信（文件传输助手、微信文件等）。
2. 打开小程序 → `设置 → 备份与恢复 → 恢复`。
3. 选择该 `.dvmini.json`，等待 Raw Validator 校验通过后确认恢复。
4. 恢复完成后**彻底关闭小程序再重新打开**，从冷启动开始计时检查。

> 这样一次注入同时验证：Raw Validator、恢复、月份分片、分类、预算、周期、统计、搜索 UI，而非只测渲染。

## 4. 数据正确性核对（与 expected 对账）

每档恢复后，对照 `realistic-<N>.expected.json` 核对，UI 看着正常但口径错也要 FAIL：

- [ ] 恢复账单数 = expected `totalBills`。
- [ ] 账本总支出、总收入 = expected `totalExpenseCents` / `totalIncomeCents`。
- [ ] 分类占比各分类金额之和 = 本月（或累计）总支出。
- [ ] 每日花费趋势各日之和 = 当月支出。
- [ ] 年度 12 个月支出之和 = 年度总支出。
- [ ] 最大单笔支出 = expected `largestExpense`，点击可打开对应账单。
- [ ] 最高消费日 = expected `topExpenseDay`。
- [ ] 搜索用例数 = expected `searchCases`（关键字「咖啡 / 红包 / 退款 / 工资」，注意「工资」会命中分类名）。
- [ ] 日价物品数 = expected `dailyValueOnlyBills`，且不进入普通支出 / 预算。

## 5. 判定与升级建议

- 三档全部 ☐ 勾选、无 FAIL、数据对账闭合 → **真机 Scale Gate 通过**，v1.3.0 具备长期使用能力。
- 若 30k 在某操作（尤其 A18 首次搜索快照、A3 统计首开、A8 切月）明显卡顿：
  - 记录具体操作、等待秒数、机型与截图，反馈后针对该路径优化（如搜索首次快照加载、按月分片索引），**不要提前做分页 / SQLite 等无数据支撑的改造**。
- 若 30k 已完全流畅，无需再为证明极限上 50k 真机；50k 仅保留在 Node Stress Gate（`npm run perf:realistic`）。
- 任一 FAIL 修复后，从该档注入开始重跑相关检查项。
