## 1. 为什么发这一版

1.5.1 的 CHANGELOG 与 README 写了「柱状图单元素硬停渐变切 6 档明度，已落地」。**这是错的**。

实测（devtools Skyline，复现 3 次）：

- 把多色标硬停写进 `components/statistics-panel/statistics-panel.wxss` 的 `.bar--exp` 后，读该元素的计算样式 **`background-image` 恒为 `null`**（`background-color` 正常生效），柱体像素自上而下**没有任何台阶**。
- 同样的渐变用**行内样式**注入同一元素，立刻正常：红/蓝/绿交界是锐利直线，只有 1 个设备像素的抗锯齿。
- 三种写法均不渲染：`background-color` + `background-image` 长写 / `background: <色> <渐变>` 同层简写 / `background: <渐变>` 简写 + `background-color` 长写。

**结论：不是渐变不支持，是组件这一层样式管线把它丢了。**

另外：`8fb0d72` 那次提交把开发当时未完成的实验态（写死浅色 alpha 的多色标硬停，实测不渲染）扫进了仓库。本版已改回可用状态。

## 5. 柱状图下一步（需客户拍板）

**方案 A（推荐）：改用 Canvas 2D 画柱状图**
与日价曲线同一套「同一路径描三遍」思路。整块绘图区只要 1 个 `canvas` 元素，元素数反而从 31 个 `view` 降到 1 个。代价：柱状图从 WXML 布局改为 Canvas 绘制，**日期标签布局与点击命中判定都要跟着重写**，属结构性改动。

**方案 B：每根柱拆 2~3 个子元素**
按 31 根柱算需 62~93 个元素，超出元素预算（40），不做。

**方案 C：维持现状**
柱子保持软过渡，只保留地面槽。视觉上与另外三张不完全统一，但零风险。

## 6. 教训（写进项目记忆）

1. **「传得进去」和「渲染得出来」是两件事。** 行内样式验证通过 ≠ 组件类规则通过。凡是要写进 `.wxss` 的图形属性，必须用**组件内真实类规则**验一次，并**读计算样式 + 看像素双证**。只在行内元素上验，会得出反向结论。
2. **读计算样式也要防脏**：Skyline 下 `element.style()` 给出的 `null` 才是真凭据，像素只是辅证；反过来只看截图会把「没实现」误判成「实现了」。
3. **别在共享工作区做临时实验**：三版实验性 wxss 被队友一次性 commit 进仓库。实验一律先备份到临时目录，或改用行内注入，不动产品文件。
4. **一个 IDE 会话只干一件事**：本轮 8 次会话里 4 次白等，预算基本砸在重启上。
