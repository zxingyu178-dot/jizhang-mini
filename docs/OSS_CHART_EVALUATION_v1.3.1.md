# OSS 图表方案评估报告（v1.3.1）

> 评估日期：2026-10-29
> 评估基线：v1.3.0（HEAD `a1621f0`）
> 评估目标：为「分类占比」圆环选择可交互、可维护、适配 Skyline 的图表方案；允许复用经过验证的开源项目，取其精华、去其糟粕，不把「零依赖」当作不可违反的目标，也不未经评估引入整个大型图表库。
> 硬约束：不依赖网络、不突破微信包体限制、不破坏页面滚动 / Swiper / Bottom Sheet / 主题切换、不升级数据合同。

## 二、方案 A：自研 SVG + 命中检测

- **实现方式**：复用 `data/statistics/donut.js` 作为圆环几何与分段数据唯一来源；新增不依赖 `wx` 的命中检测纯函数，组件以 `bindtouchstart` 取触摸坐标，结合容器 `boundingClientRect` 映射到 SVG viewBox，按圆环内外半径与「12 点方向顺时针」角度区间定位分段。
- **POC 验证（真实运行，非 README 判断）**：临时 POC 脚本覆盖各分段中点、12/3/6/9 方向、中心孔、外部、内缘 / 外缘边界共 **14 项断言全部通过**。命中检测数学与 `buildDonutArcs` 的绘制顺序、起始位置、方向完全一致。
- **交互能力**：分段点击、选中高亮、中心切换分类名 / 金额 / 占比、图例同步高亮均可实现；tooltip 由中心 WXML 承担，不依赖 DOM。
- **触摸与滚动**：`bindtouchstart` 只在圆环容器内响应，不阻止冒泡，不影响 scroll-view 滚动；无 Canvas 同层组件，天然规避手势冲突。
- **包体**：不新增运行时库，仅增加小量纯函数与 WXSS；主包维持在现有约 562 KB 水平。
- **主题 / 离线**：轨道色已主题感知，分段为固定可读色；纯本地计算，完全离线。
- **维护成本**：命中逻辑为确定性数学，可完整单测，维护权在本项目；不依赖外部发版节奏。
- **结论**：可靠，且与现有架构一致。

## 三、方案 B：ecomfe/echarts-for-weixin

- **项目地址**：https://github.com/ecomfe/echarts-for-weixin
- **版本事实**：仓库仅 62 个 commit，Open Issues 约 502；7.5k star / 1.6k fork。官方未提供语义化版本标签，需固定到具体 commit。
- **许可证**：**BSD-3-Clause**；采用须保留 LICENSE 与版权声明。
- **原生 / Skyline**：基于 Canvas（基础库 ≥2.9.0 默认 Canvas 2d，可回退旧 Canvas）；官方文档未明确声明 Skyline 兼容，Canvas 同层组件在 Skyline 下的表现需真机验证，存在不确定点。
- **交互能力**：ECharts 能力完整，支持 pie 选中、legend、tooltip、事件；功能远超本项目单一圆环需求。
- **包体（关键劣势）**：`ec-canvas` 目录约 **1006 KB**（含完整 echarts.js），单页面即约 1010 KB，直接逼近主包 2 MB 上限；必须在线定制裁剪并考虑分包，集成与裁剪成本高。
- **主题 / 离线**：支持主题配置，可离线；但定制构建工具链与本项目现有流程不匹配。
- **已知问题**：官方列出安卓 transform 缺陷、iOS 半透明变深、渐变越界等；issue 积压、维护趋缓。
- **结论**：**不建议**。能力过剩、包体代价过大、Skyline 与维护风险高，不符合最小复杂度。

## 四、方案 C：antvis/F2（`@antv/f-wx`）

- **项目地址**：https://github.com/antvis/FEngine ；引擎 `@antv/f2`，微信组件 `@antv/f-wx`
- **版本事实**：`@antv/f-wx` 最新 **1.10.0**（约 6 个月前发布），`@antv/f2` 5.x（MIT）；周下载量较小、npm 依赖方 0。
- **许可证**：**MIT**；须保留版权与许可声明。
- **原生 / Skyline**：基于 Canvas（FEngine 封装）；接入需配置 **JSX Transform（babel 编译）**，本项目是微信原生 JS、无 JSX/babel 构建链，引入会新增编译步骤，对现有工程侵入明显。
- **交互能力**：图形语法强大（50+ 图表），支持饼图选中、图例、tooltip；对单一圆环属于过度设计。
- **包体**：F2 核心无交互 gzip 约 44 KB、带交互约 56 KB，加上 wx 适配与运行时；体积可控但需配合构建链。
- **主题 / 离线**：支持主题、可离线。
- **维护成本**：官方仍在维护，但小程序适配使用面较窄（依赖方少），Skyline 下 Canvas 行为仍需真机验证。
- **结论**：**不建议**。主要阻碍是 JSX/babel 构建链与 Canvas 引入，收益与本项目单一圆环需求不匹配。

## 五、方案 D：uCharts

- **项目地址**：https://gitee.com/uCharts （官网 ucharts.cn）
- **版本事实**：持续更新，社区活跃，主要面向 uni-app / 跨端；原生微信小程序需自行拷贝组件并适配。
- **许可证**：**Apache-2.0**；须保留版权、许可证与 NOTICE 声明。
- **原生 / Skyline**：基于 Canvas 2d；在 Skyline 下 Canvas 同层与触摸需真机验证；社区有 Canvas 2d 适配讨论。
- **交互能力**：支持饼 / 环图、图例、点击事件，图表类型全。
- **包体**：跨端封装后 u-charts.js 约 **93 KB**（为三者中最小的 Canvas 方案），但仍是额外运行时，且需删裁无关图表。
- **主题 / 离线**：支持自定义颜色、可离线。
- **维护成本**：生态以 uni-app 为主，原生微信集成需自行维护改造；同样重新引入 Canvas 风险。
- **结论**：是 Canvas 方案中相对轻量的备选，但仍需引入 Canvas 与原生集成成本，相对自研 SVG 无明显优势。

## 七、POC 与最终选型

**POC 结论**：方案 A 的命中检测为不依赖 `wx` 的确定性纯函数，14 项边界断言全部通过，且与现有 SVG 绘制几何严格一致；触摸不阻断页面滚动，不新增包体与构建链。

**最终选型：采用方案 A —— 保留并增强自研动态 SVG，新增纯函数命中检测。**

理由：

1. 三个开源候选均基于 Canvas，会重新引入本项目此前刻意规避的 Canvas 生命周期 / Skyline 同层 / 真机不确定点（日价 Canvas 真机 Gate 仍在待验收状态）。
2. echarts 包体约 1 MB、F2 需 JSX/babel 构建链、uCharts 需原生改造，均与「单一分类圆环」的实际需求不匹配，违反最小复杂度。
3. 自研命中检测已被 POC 证明可靠、可完整单测、完全离线、主题可感知、包体几乎不增加，且维护权在本项目。
4. 「取其精华、去其糟粕」的落地：吸收开源图表在「分段选中、中心信息切换、图例高亮、点击钻取」的交互设计方法，但不引入其框架、Canvas 与依赖；保留本项目本地存储、整数分金额、隐私设计与紫黑毛玻璃视觉。

> 本版不新增第三方依赖，因此暂不需要 `docs/OSS_ATTRIBUTION.md`；若后续引入任何开源代码，将按规范固定版本、保留许可声明并补该文件。
