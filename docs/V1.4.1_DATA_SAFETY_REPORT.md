# v1.4.1 Gate 1 · 数据安全报告（fail-closed 隔离）

- 优先级：最高（先于性能与 UI）
- 目标：**隔离成功才能删除；隔离失败必须中止破坏性操作**
- 涉及文件：`data/quarantine.js`、`data/backup.js`、`packages/importer/core/commit.js`、`tests/quarantine-rollback.test.js`

---

## 1. 修复前的问题

`data/quarantine.js` 采用「失败降级」：

- 目录创建失败、文件复制失败、meta 写入失败都被内部 `try/catch` 吞掉；
- `quarantineUnreadableMonths()` 只返回 `ok`，调用方 `backup.js` 完全不看返回值；
- `restoreBackup()` 在隔离调用之后无条件 `ledger.listMonths().forEach(fs.remove)`；
- `rollback()` 同样无条件先删除再写安全点。

结果：**原始损坏分片尚未成功保存，系统就已经把它删除**，与数据保护目的相反。

本次把隔离结果改为结构化 `safeToProceed`，并把「删除」改为受该值闸门控制。

## 2. 实现内容

### 2.1 `data/quarantine.js`

返回结构（完整字段）：

```js
{
  complete, safeToProceed,
  targetCount, copiedCount, failedCount, metaWritten,
  dir, items, failed, skipped
}
```

判定规则：

| 场景 | complete | safeToProceed | skipped |
| --- | --- | --- | --- |
| 无损坏分片 | true | **true** | `none-unreadable` |
| 全部转存 + 逐字节回读一致 + meta 成功 | true | **true** | `''` |
| 目录创建失败 | false | **false** | `dir-failed` |
| 任一文件复制失败 | false | **false** | `copy-failed` |
| 回读字节不一致 | false | **false** | `copy-failed`（failed 记录 `QUARANTINE_VERIFY_MISMATCH`） |
| meta 写入失败 | false | **false** | `meta-failed` |
| 未预期异常 | false | **false** | `unexpected` |

其他要求：

- 每个文件写入后立即 `readBuffer(dest)`，用 `sameBytes()` **逐字节**比较，不允许只比长度；
- `meta.json` 增加 `complete`、`verified` 字段；
- 模块自身永不抛出，由调用方根据 `safeToProceed` 决定是否中止；
- meta / 日志仍只含路径、字节数、错误码、时间、触发动作，不含金额 / 商户 / 备注 / ID。

### 2.2 `data/backup.js`：恢复状态机

执行顺序改为：

1. 校验备份格式与语义；
2. **删前隔离**（`safeToProceed !== true` → 立即抛 `QUARANTINE_INCOMPLETE`，不写安全点、不删除、不回滚）；
3. 写安全点（失败 → 抛 `SAFETY_POINT_FAILED`，现有账本未修改）；
4. `mutationStarted = true`；
5. 清分片 → 写账单 / 分类 / 设置 / 周期 → 条数校验 → 健康终检；
6. 成功返回新增 `quarantine` 摘要。

失败边界：

| 情况 | 行为 | 错误码 |
| --- | --- | --- |
| A. 隔离阶段失败 | 原始分片全部保留，不覆盖、不回滚 | `QUARANTINE_INCOMPLETE` |
| B. 安全点失败 | 原账本完全不变 | `SAFETY_POINT_FAILED` |
| C. 恢复中途失败 | 按安全点回滚，错误带 `mutationStarted/rollbackAttempted/rollbackCompleted` | 原始错误码 |
| D. 回滚失败 | 不删除安全点、不谎报成功，抛组合错误并附 `rollbackError` | 原始错误码 + `ROLLBACK_*` |

### 2.3 `rollback()` fail-closed

- 安全点不可读 / 结构不完整 → `ROLLBACK_SAFETY_UNAVAILABLE`，不清账本、不删除安全点；
- 回滚前隔离未完成 → `ROLLBACK_QUARANTINE_INCOMPLETE`，**禁止**继续 `listMonths().forEach(remove)`。

### 2.4 `packages/importer/core/commit.js`

导入失败后的救命回滚不再静默吞异常：

- 回滚成功 → 原错误带 `mutationStarted=true / rollbackAttempted=true / rollbackCompleted=true`；
- 回滚失败 → 抛组合错误（`IMPORT_ROLLBACK_FAILED` 或原错误码），附 `rollbackError`，安全点保留。

## 4. 遗留与限制（如实记录）

1. **回滚不是数据库级原子操作**：回滚仍为「清分片 → 按安全点重写」。本次做到的是「回滚前隔离失败即中止 + 安全点保留 + 明确报错」，不承诺任意中断点都能自动恢复。
2. **形状非法月份**（JSON 合法但 `bills` 非数组）会让安全点构建失败，本次转为明确错误 `SAFETY_POINT_FAILED` 并保留原始分片，不再以不可读的 `TypeError` 结束；未改变 `readMonthFile()` 的历史读口径。
3. **真机未测试**：本 Gate 全部为 Node 内存 FS 故障注入，真机文件系统行为（权限、磁盘满、并发）未覆盖，列入 Gate 5 真机验收清单。
4. 安全点文件仍位于 `<USER_DATA_PATH>/legacy/restore-safety.json`，本版不改路径与格式。
