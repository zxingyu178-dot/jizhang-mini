## 3. 已实现功能明细（按页面）

### 3.1 明细页 `pages/index`（首页）
- 顶部卡片：**当前自然月**收入、支出、结余（绿色渐变）。
- 全部账单**按日期分组倒序**展示，日期做友好化（今天 / 昨天 / M月D日）。
- 每个日期组显示当日收入、支出小计。
- 单条记录显示：分类 emoji、分类名、备注、金额（支出红色带 `-`，收入绿色带 `+`）。
- 点击单条 → ActionSheet → 二次确认后**删除**。
- 空态引导（"记一笔"按钮）；有数据时底部悬浮"＋ 记一笔"。
- `onShow` 每次进入自动刷新，保证记账后立即可见。

### 3.2 记账页 `pages/add`
- 支出 / 收入切换，配色联动（支出红、收入绿）。
- 金额输入：数字键盘，正则限制为**最多两位小数**、仅一个小数点。
- 分类网格：
  - 支出 8 类：餐饮、交通、购物、住房、娱乐、医疗、教育、其他；
  - 收入 5 类：工资、兼职、红包、理财、其他。
- 日期选择器（默认今天，可补记历史日期）。
- 备注输入（最多 30 字，可空）。
- 保存校验（金额必须 > 0），写入本地存储 → Toast 提示 → 自动跳回明细页。

### 3.3 统计页 `pages/stats`
- 支出 / 收入切换。
- 累计总额显示。
- 按分类聚合：金额、占比百分比、横向条形（宽度按占比）。

### 3.4 数据与工具层
- `utils/db.js`：`CATEGORIES`（分类字典）、`addRecord`、`deleteRecord`、`summary`（收入/支出/结余）、`groupByDate`（按日分组）、`categoryStats`（分类占比）、`getCategory`。
- `utils/util.js`：`formatDate`（YYYY-MM-DD）、`formatMoney`（千分位 + 两位小数）、`genId`（唯一 ID）、`friendlyDate`、`pad`。
- 排序：按日期倒序、同日按创建时间倒序。

**记录（record）数据结构：**

```json
{
  "id": "记录唯一ID（时间戳36进制 + 随机串）",
  "type": "expense",            // expense=支出，income=收入
  "amount": 25.5,               // 数值，保留两位小数
  "category": "food",           // 分类标识，见 CATEGORIES
  "date": "2026-10-15",         // YYYY-MM-DD
  "note": "午餐",               // 备注，可为空
  "createdAt": 1728969600000    // 创建时间戳（毫秒）
}
```

## 5. 关键设计约束（规划时必须遵守）

1. **原生小程序**：不引入框架、不依赖构建工具链；新增页面遵循原生 Page/Component 模式。
2. **纯本地、无网络**：当前版本不发起任何 `wx.request`，不依赖服务器域名；数据仅存 `wx.Storage`。
3. **UI 全中文**：界面文案、Toast、弹窗均使用中文。
4. **配色规范**：主色微信绿 `#07c160`；支出 `#fa5151`；收入 `#07c160`；背景 `#f5f6f8`；卡片白底圆角。
5. **图标方案**：tabBar 用自绘 PNG（`images/tab`），分类用 emoji 占位。
6. **安全**：AppSecret、任何密钥禁止入库；当前代码不涉及密钥。
7. **数据兼容**：若 v0.1.0 调整本地存储结构，需保证旧数据可平滑迁移（建议做 schema 版本号 + migration），不得让已记账用户数据丢失。

## 7. 当前已知限制 / 技术债（v0.1.0 的改进来源）

1. **数据安全风险（最高）**：纯本地存储，卸载小程序、换手机、清缓存会导致账单永久丢失，**当前无任何备份/导出能力**。
2. 记录**只能新增和删除，不能编辑**（记错只能删了重记）。
3. 明细页汇总只看**当前月**，列表却是全部记录，**缺少按月切换 / 月度账单视图**。
4. 统计页为**全量累计**分类占比，**缺少按月统计、趋势、预算**。
5. 分类**固定不可自定义**，记录**没有具体时分**。
6. 无搜索、无筛选、无账单导出。
7. 工程上：数据逻辑集中在 `db.js`，尚未抽象为组件；无数据迁移机制；表单校验较简单。
8. 发布材料未准备：服务类目、功能页面、隐私保护指引（即使纯本地，部分类目审核也会要求）。

## 8. v0.1.0 规划输入（候选需求池，供 ChatGPT 取舍）

> 以下为建议，**最终范围请 ChatGPT 结合 MVP 原则与用户确认后确定**。标注的优先级为建议。

### P0 · 数据安全（强烈建议进入 v0.1.0）
- 数据导出/导入：导出为 JSON（或 CSV）到微信聊天/文件，支持再次导入恢复（解决纯本地最大痛点）。
- 账单编辑：修改金额、分类、日期、备注。
- 本地存储 schema 版本化与迁移机制。

### P1 · 核心记账闭环
- 按月切换查看 + 月度账单页（月度收入/支出/结余/笔数）。
- 记录增加具体时间（时分）。
- 分类管理（新增/停用自定义分类，预置分类保留）。
- 备注历史/快捷选择。

### P1 · 统计与预算
- 按月统计、收支趋势（折线/柱状）、每日支出。
- 月度预算设置与超支提醒。

### P2 · 体验与工程化
- 账单搜索、按分类/类型筛选。
- 首次引导、空态、金额输入小计算器。
- 自定义组件抽取（金额、分类选择、空态）、统一常量与工具、单元测试。

### 需用户拍板的架构决策（影响 v0.1.0 边界）
- **是否引入云同步 / 后端**（如微信云开发）：可解决备份与多设备，但会改变"纯本地、无登录"定位与审核范围。
- **是否需要账号体系**：云同步通常依赖。
- **是否多端**（H5/其他平台）：当前为原生，若未来要多端需评估 Taro/uni-app 迁移成本，v0.1.0 不建议同时做。

### 发布准备（与开发并行）
- 完善小程序名称、头像、简介；确定服务类目（工具类）。
- 准备隐私保护指引（说明本地存储用途）；必要时准备提审说明。
