## 二、键盘到底是怎么收起来的（真实链路，白话 + 行号）

### 2.1 为什么必须绕开 iPhone 数字键盘

`input` 的 `confirm-type` 只对 `type="text"` 有系统完成键；`type="digit"` / `type="number"` 的 iPhone 数字键盘**没有「完成」键**，也没有可绑定的 `bindconfirm`。所以代码里没有、也不可能依赖原生完成键——做法是**在输入框右侧自绘一个页面内「完成」**（5 处，均 `catchtap`，不走系统键）：

| 位置 | 行号 |
|---|---|
| 记账金额 | `components/bill-form/bill-form.wxml:23-28` |
| 日价金额 | `components/daily-value-form/daily-value-form.wxml:33-38` |
| 周期金额 | `pages/recurring/recurring.wxml:68` |
| 周期间隔 | `pages/recurring/recurring.wxml:85` |
| 每日预算 | `pages/budget-settings/budget-settings.wxml:25` |

### 2.2 点「完成」之后发生什么（五步）

1. `catchtap → onAmountDone()`（例：`bill-form.js:184-187`）
2. → `keyboard.releaseInputFocus(this, 'amountFocused')`（`utils/keyboard.js:43-64`）
3. → `setData({ amountFocused: false }, 回调)`：**通过 `focus="{{amountFocused}}"` 这个受控绑定把焦点标记置 false**（`bill-form.wxml:21`、`daily-value-form.wxml:31`、`recurring.wxml:67` 与 `:80`、`budget-settings.wxml:23`），即 WeChat 侧由 true→false 触发失焦；**不依赖 blur 事件来收键盘**
4. → 回调里调 `wx.hideKeyboard({ complete, success, fail })`（`keyboard.js:28`）
5. → **120ms `setTimeout` 兜底 resolve**（`keyboard.js:34`）：complete 不回调 / 基础库不认参数 / API 抛错，都会在 120ms 后继续，**Promise 永不悬挂** → 不会出现"点了完成，Sheet 永远关不上"的死锁

**关键设计取舍（正确）**：`onAmountBlur` 只同步值、**不调 hideKeyboard**（`bill-form.js:179-183` 注释明确），所以「金额→商户」切换时键盘**不会关掉再重开**。

### 2.3 关闭与返回的分层（没有第二套实现）

| 动作 | 实现 | 行号 |
|---|---|---|
| 关 Bottom Sheet | `close()` 先 `await hideKeyboard()`，再播 280ms 下滑动画，再 `closed` | `components/bottom-sheet/bottom-sheet.js:30-45` |
| 快速开关不打架 | `_closeSeq` 序号：关闭期间重新打开则本次关闭作废 | `bottom-sheet.js:24`、`:32-37`、`:40` |
| 页面返回 | `isKeyboardOpen()` 为真 → **首次返回只收键盘**；否则「先收键盘再 navigateBack」，含 `_backing` 防连点退两级 | `components/page-header/page-header.js:31-52` |
| 删除账单确认 | 先 `hideKeyboard()` 再 `wx.showModal` | `bill-form.js:210-229` |
| 周期删除 / 补记确认 | 同上 | `recurring.js:231-249`、`:394-406` |
| 预算保存 | 先置 `amountFocused:false` 再 `hideKeyboard()` 再落库 | `budget-settings.js:88-99` |
| 键盘高度监听 | **全局唯一一处** `wx.onKeyboardHeightChange`，`app.js:23` 启动一次 | `utils/viewport.js:51-77`；`app.js:23` |
| 只读状态复用 | `isKeyboardOpen()` 只读 `lastKeyboardHeight`，**不新增监听** | `utils/viewport.js:84-87` |

**iOS 特判：没有，也不需要。** `utils/keyboard.js` / `utils/viewport.js` / 各表单里**没有任何 `platform === 'ios'` 分支**（`device.js:78-81` 有 isIOS 字段但键盘链路未使用）。这是好事——双端同一条链路，不存在机型分叉导致的"iOS 修好、Android 坏掉"。

## 四、缺陷清单

### P1-01 记账 / 日价 / 周期三处保存入口无防连点，连点即重复写入

| 项 | 内容 |

| 严重度 | **P1**（脏数据：重复账单 / 重复周期规则 + 重复补记账单；A9 直接不达标） |

| 判定依据 | 三个 handler 都**没有任何时间锁/状态锁**：`bill-form.onSubmit` 只判 `canSubmit`，`daily-value-form.onSubmit` 只判表单有效性，`recurring.onSave` 只判 `amountCents/categoryId/startDate`。三者都**不置 busy 标记、不重置 `canSubmit`**，因此同一份 data 下可被连续调用并各自成功写库。反向证据：同一批改动里 `budget-settings.js:83,89` 明确加了 `_saving` —— 说明团队自己认为这个锁是必需的，只是漏了另外三处。 |

| 真机触发路径 | 1) 点金额输入（键盘弹起）→ 2) 输入 12.34 → 3) **不点「完成」**，直接快速连点「确认记一笔」两次 → 第一次点击进入 `onSubmit`，父页 `onBillSaved` 只把 `sheetShow=false`，`bottom-sheet.close()` 要**先等 `hideKeyboard()` 完成**（键盘打开时＝键盘收起动画耗时，iOS 约 200–300ms）才把 `visible` 置 false，此窗口内面板仍可命中 → 第二次点击再写一条。周期保存窗口更长（`runRecurringGenerator()` 异步落库后才关 Sheet）。 |
